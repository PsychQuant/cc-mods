# progress-bar

Claude Code 的 mod:Claude 用 Bash 在背景跑指令(`run_in_background`)時,在提示列上方畫一條進度條。
兩次讀數之間長條照樣往前走,並顯示還要多久。

```
▕██████▍░░░░░░░░░░░░░▏  32.1%  Run full pytest suite · 12m · 還要約 25m
⠹ Install package dependencies · 45s · Downloading numpy-2.3.1.tar.gz
✓ Build documentation site 100% · completed · 3m
```

## 它怎麼知道跑到幾趴

mod 看不到程式內部,只讀程式寫出來的輸出:

1. 背景 Bash 指令開始時,記下它的任務 id 與要讀的檔 —— 任務的輸出檔,加上指令裡 `>`、`>>`、`tee` 寫到的檔。
2. 每 2 秒讀一次那些檔的尾端(檔沒變就不讀),取**最後一個 0–100 的百分比**(`42%`、pytest 的 `[ 29%]`);
   讀不到百分比就顯示最後一行與經過時間。
3. 收到背景任務結束的通知時打勾(或打叉),15 秒後收起。
4. 每一輪結束時,對照引擎列出的背景工作(shell、subagent、workflow、monitor):**還在跑、但還沒被記下的接上**(例如 mod 載入之前就開始跑的),shell 讀它重導向的檔或這個 session 輸出資料夾裡的 `<id>.output`(資料夾從第一個背景 Bash 的結果學到),其他種類只顯示名字與經過時間;**記著、但已經不在清單裡的當作結束**,沒有結束通知的種類也收得起來。接上的任務沒有開始時間,經過時間從接上的那一刻算。
5. 跟同一條 band 上的其他 mod 疊著畫:先拿下面的 plugin 畫的東西,自己的列放在上面,不取代它。

## 讀數之間怎麼往前走(cc-mods#1)

程式不會每秒都印百分比(pytest 一整行才印一次),所以畫面上的百分比是估計值,每 250 ms 算一次:

1. **速率**:讀數進指數權重的 local linear regression(只用過去的讀數,越舊權重越小),得到現在的速率。
   讀數少時往同一個指令過去的速率收縮。開始時間已知時,`(開始, 0%)` 算第一個點。
2. **目標**:以最後一個真實讀數為錨,依速率往前外插;外插會飽和、最多領先一個典型步幅 ——
   讀數該來沒來,本身就是「變慢了」的訊號。
3. **顯示值**:跟著目標走,落後時追上、超前時變慢。**只增不減、不會停**(最低速度是剩下距離的 1/3600 每秒),
   任務結束前不到 100%(上限 99.5%)。顯示值不能往回,所以寧可落後(追得回來)也不要超前(收不回來)。
4. **歷史**:跑完(completed)的背景指令,長度以**完全相同的指令字串**記在這個 mod 的 store(本機,跨 session;
   每個指令最近 5 次、最多 200 個指令)。同一個字串再跑時,沒有讀數也依經過時間 ÷ 過去長度的中位數畫長條;
   跑得比平常久寫「比平常久」。
5. 讀數往回掉超過 5 個百分點(一個指令串了好幾段)視為新階段;有歷史時改依經過時間畫。
6. 沒有讀數也沒有歷史:轉圈。手感的參數都在 `hooks/est.ts` 頂端。

## 限制

- 只看得到程式自己印出的百分比。沒有印進度、也沒有跑過的程式只會轉圈,顯示最後一行與經過時間。
- 指令字串裡有時間戳或暫存路徑的(`$(date …)`、`mktemp`),每次字串都不同,查不到歷史。
- 歷史存的是指令字串原樣,只在本機這個 mod 的 store,不送到任何地方。
- 指令寫到的檔要是絕對路徑,或只用到 `HOME`、`TMPDIR`、`CLAUDE_JOB_DIR`、`PWD` 這四個變數(與開頭的 `~`)。
  相對路徑要看指令當時的工作目錄,`cd` 之後猜不準,所以不讀。
- 進度列用 `\r` 原地重畫的程式(pip、curl)也讀得到,因為 `\r` 算換行;顏色碼會先拿掉。
- 同時最多顯示 6 個任務;沒收到結束通知的任務 6 小時後收起。
- 同一條 band 上排在它上面、又不呼叫 `next(e)` 的 mod,會把它蓋掉(例如 token-weather 0.1.0);排在它下面的會一起畫出來。

## 開發

`claude plugin test plugins/progress-bar` 跑測試。型別檢查用 API 與內建工具的型別(`.claude-plugin/types/claude-code`、`claude-code-tools`);接了很多 MCP 工具的機器上,引擎產生的 tsconfig 把 MCP 工具的型別也算進去,`tsc` 可能報 TS2589(型別展開太深),那不是程式的錯。

## 安裝

在 Claude Code 的提示列輸入:

```
/plugin marketplace add PsychQuant/cc-mods
/plugin install progress-bar@cc-mods
```

## 檔案

| 檔 | 內容 |
|---|---|
| `hooks/register.tsx` | hooks module:`tool.call`(記下背景任務)、`session.append`(結束通知、寫歷史)、`session.start`(每 2 秒讀檔、每 250 ms 算顯示值)、`ui.render`(畫在提示列上方) |
| `hooks/est.ts` | 純函式:速率估計、目標、顯示值的控制器、歷史 |
| `hooks/parse.ts` | 純函式:讀百分比與最後一行、找重導向的目標、展開路徑、畫長條(八分之一格)、還要多久 |
| `types/index.d.ts` | `$.state` 的型別合約 |

這是 function hooks 的 plugin(mod):`hooks/hooks.json` 寫的是 `{ "modules": [...] }`,不是命令 hook 的 `{ "hooks": ... }`。
